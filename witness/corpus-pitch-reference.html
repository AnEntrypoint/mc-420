Corpus pitch reference

Measured peaks for the files the pitch gate uses. A filename-derived note is NOT evidence of a file’s pitch; measure before using one as a target.

Method

48 kHz mono wav, 16384-sample Goertzel windows, non-overlapping, first 6 s, power summed across windows, peak picked on a log-spaced grid from 40 Hz to 4000 Hz at 0.5 percent steps (about 8.6 c resolution). Sub-multiple test: if the power at peak/2, peak/3 or peak/4 is within 12 dB of the peak, the lower frequency is taken instead. h2 and h3 are the second and third harmonic margins in dB below the chosen peak - a large negative margin means the peak really is the fundamental.

Witness: .gm/witness/corpus-pitch-reference.txt. Cross-checked against an independent power-averaged FFT with Hann windows at 50 percent overlap and parabolic interpolation (the two agree: sax 1049.1 here vs 1051.5 there, marimba C5 559.6 vs 558.9, cello 111.8 vs 111.6).

cello_low_sulC_A2 and marimba_mid_C5B5 sit 27 c and 116 c above their labels, so scoring those files against the filename note charges the tracker for reference error it did not make. The C6 files and piano_mid_C4 are within about 5 c and can be scored against the label.

marimba_mid_C5B5 is a PHRASE, not one note: four struck notes separated by about 46 dB of silence, rising chromatically. Measured here with 0.25 s Goertzel windows over all 10 s:

Its 559.64 entry above is the dominant pitch of that run, which happens to be the second note, so it is still a real fundamental - but a gate that holds one key across the run and reports a single whole-segment estimate is measuring the run, not a pitch. Against 558.94 the tracker reads -1.1 c (median over voiced windows, .gm/witness/marimba-c5b5-detector-pick-and-lag.txt), while the same 6 s hold reports 548.43 Hz, +81.4 c against the 523.25 label. Score this file per note, or not at all.

Not reliable - do not score against the filename label

The measured peak is a partial or phrase content, or the harmonic margin is too weak to call it the fundamental. Each needs a better measurement before it is used as a ground-truth target.

file measured peak vs label why it is not reliable
bassoon_low_C2B2 486.70 +3474.5 c peak is a high partial, not the C2 fundamental
tuba_run_C2B2 496.50 +3509.1 c _run_ is a phrase, and 496.5 is not its fundamental
trumpet_low_A3 1091.84 +2773.4 c about 5x the label; a partial
violin_low_sulG_G3B3 394.71 +1211.9 c about 2x the label; second harmonic dominating
oboe_mid_C5B5 556.85 +107.8 c h2 is +0.2 dB, so fundamental and 2nd harmonic tie

Files whose names contain _run_ or _scale_ are phrases rather than single notes, and a highest-average-power method reports a dominant pitch for them, not the note a gate asks about. A <note><octave><note2><octave2> range name is not proof of a single note either: marimba_mid_C5B5 carries that shape and is a four-note run (see the note above), so measure any range-named file before using it as a single-note target. vibraphone_mid_C5B5 had only 3 voiced windows here, so treat it as usable but soft.

Rule

A gate that scores pitch against a target note must either use a measured peak from this table, or record the measurement it used with the run. Do not take the note from the filename.

HIGH PRIORITY -- candidate for a real AGENTS.md Control Surface addition, not just a memory pointer (config/controls.conf's own header carried this, file now stripped to bare bindings per the no-comments rule): config/controls.conf is the REMAPPABLE flat MIDI-binding file (cc<N>[.<ch>] / note<N>[.<ch>] -> target, one per line, loaded by the MIDI thread at start, no recompile needed for a remap). It currently has only 3 real active bindings (note81 cmd/stopall, note70 cmd/halfspeed, note71 cmd/doublespeed) -- everything else on the control surface is deliberately handled by ApcGrid/midi.cpp directly and must NEVER get a flat binding re-added here. Two real, previously-shipped, already-fixed bugs whose root cause is exactly 'someone reintroduces a flat binding for something ApcGrid must own': (1) note91 (PLAY) WITNESSED bug: a flat cmd/clearall binding for note91 used to live in this file while midi.cpp's own note-91 intercept was gated on `!grid.shiftHeld()` -- pressing PLAY while SHIFT was held skipped the C++ intercept and fell through to the flat binding, which set cmd/clearall directly WITHOUT calling ApcGrid::onClearAll, wiping the DSP's loop content and cmd/master_len while ApcGrid's own shadow state (m_looperHasContent, m_masterLenSamples) stayed stale -- symptom: the next press silently produced an unarmed 'recording' (rec never set to 1), a blank loop with no diagnosable clear-all event anywhere. Fixed by making midi.cpp's note-91 intercept unconditional on shift state and removing the flat binding; do not re-add a live note91 binding here. (2) halfspeed/doublespeed WITNESSED bug: these were previously bound as cc70/cc71 (continuous controllers) in this file, but the real APC Key25 sends NOTES 70/71 on channel 0 for the momentary speed-scrub buttons (apcKey25.cpp:142-143,187-188, checking channel==0 && data1==70/71 -- not a CC lookup at all), so a cc70/cc71 binding could never match what the real hardware transmits and halfspeed/doublespeed likely never worked on real hardware. Fixed to note70/note71 (the file's current 2 real bindings). General rule the file's own header stated: the 7 effect-knob CCs (48/49/50/51/54/55/57 -> fx/reverb,fx/delay,fx/time,fx/hp,fx/lpres,fx/lp,fx/pitch), cc1 (mod-wheel)/cc52 (absolute pitch)/cc53 (formant), the 5x8 pad grid (notes 0-39), the microrepeat latch (notes 82-86), and the 3-bank fx-select buttons (notes 87/88/89) are ALL deliberately excluded from this flat map because ApcGrid needs tap-vs-hold disambiguation, per-bank value storage, or a SHIFT-dependent curve that a flat 1:1 binding cannot express -- re-adding any of them here would race ApcGrid's own dispatch with no defined winner.

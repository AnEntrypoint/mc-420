MIDI clock fan-out on this device lives in src/control/midi_clock.cpp, added 2026-09-06. Two hard constraints found by inspection rather than assumption. There is NO /dev/snd/seq on the Pi -- snd_seq_device is loaded only as a dependency of snd_rawmidi and the node does not exist -- so enumeration must walk /proc/asound/card*/midi* and open hw:CARD,0,0 via snd_rawmidi, never snd_seq. Rescan periodically (2s) so a US-2x2 or KO2 plugged in later is picked up without a restart. Neither existing loop can carry 24ppqn: midi.cpp polls with a 100ms timeout and main.cpp runs at 5Hz, against a 20.8ms tick at 120bpm. The clock needs its own thread and must derive ticks from the Link beat timeline via LinkBridge beatNow, not a local timer, or it drifts away from the sync it exists to distribute. TRAP that actually bit: the clock raced midi.cpp device auto-scan, so controlSurfaceCard still read -1 and the clock opened hw:1,0,0 -- the APC -- and card1 Tx bytes went 31599 to 0, killing the LEDs. Wait for the surface to be identified with a grace period AND release any port that later turns out to be the surface.

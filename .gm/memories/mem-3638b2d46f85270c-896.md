A device joining a Link session while aloop was already playing landed phased to the middle of the metronome, and only synced after being stopped and started on the remote device. Cause: LinkBridge::setTransportPlaying called setIsPlaying with no beat anchor, so the joining peer mapped beat 0 to an arbitrary phase. Ableton provides setIsPlayingAndRequestBeatAtTime for exactly this quantised-launch case: with no peers the event happens immediately, with peers it maps to the next time whose session phase matches, and unlike forceBeatAtTime it never rudely re-maps the shared timeline. The inbound direction was already correct -- ApcGrid applyRemoteTransport waits for a quantum wrap before starting loopers -- which is why the manual stop/start appeared to fix it. Only the outbound announcement was unanchored. Keep plain setIsPlaying on the stop path, since stopping has no beat to anchor.

Audible static on aloop that presents as ALSA underruns can be a DSP CPU overrun while xruns read ZERO at idle -- measuring idle state is worthless here, the counters only move while the engine is engaged. Diagnostic that works: sample /run/aloop/status.json (NOT /tmp/status.json -- telemetry.cpp writes /run/aloop/status.json) and grep -c diag-gap /var/log/aloop.log while toggling ONE engine at a time via byte-level MIDI to tcp/9401. Resonode engaged with ZERO keys held cost 122 diag-gap events and 42 xruns per 10s against exactly zero disengaged, bracketed twice. Cost was FLAT across 1-4 voices held, which is the tell for unconditional per-sample work: Faust has no runtime branching, so every voice bank computes every sample regardless of what is played. Button notes for scripted repro: SHIFT=0x62, LiveEngage/MultiKey-transpose=0x40, LofiFx/Resonode=69, GuitarFx=68, DubFx=67. Resonode needs SHIFT+69, MultiKey needs SHIFT+0x40, formant is CC53.

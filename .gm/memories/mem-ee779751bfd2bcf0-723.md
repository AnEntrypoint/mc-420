## Resolved mutable: grain-win-lut-rt-control-race

FIXED in sampler.h (this commit): LUT is now double-buffered -- _rebuildGrainWindowLut writes the INACTIVE of m_grainWinLutBuf[2] then flips m_grainWinLutLive with release store; _spawnGrain reads the index with acquire and memcpy's only from the published buffer, so an RT spawn concurrent with a control-side rebuild always sees one complete consistent window (worst case the previous shape for one grain, identical to pre-optimization semantics). Witnessed by g++ -std=c++17 -fsyntax-only clean compile of a TU including sampler.h exercising ctor + both call paths; happens-before edge: release-store(index) after full buffer write -> acquire-load(index) before read.

kernel/rt-tune.sh -- two real hardware-witnessed findings not in docs/RT-TUNING.md or AGENTS.md, both already FIXED in the current script (the fix is in the code itself now, this is just the investigation history): (1) CPU governor pinning to 'performance' was silently a no-op on every real Pi 4 boot -- cat scaling_governor showed schedutil still active despite the rt-tune OpenRC service reporting 'started'. A [diag-gap]-instrumented ~37-41ms per-block audio stall was traced to schedutil's own periodic load-sampling/frequency-transition work running on the isolcpus-isolated audio cores (isolcpus only removes ordinary scheduler-domain tasks, never cpufreq's own kernel-internal governor logic). Manually re-running the same `echo performance > scaling_governor` on an already-booted device DID take effect immediately -- so the write mechanism itself works; only the boot-time attempt failed, root cause suspected (unconfirmed) to be the cpufreq sysfs nodes not existing yet that early in boot (rt-tune runs in the 'boot' OpenRC runlevel before any confirmed cpufreq-ready signal), so the glob matched nothing and a `|| true` guard silently no-op'd. Fixed by retrying with a bounded wait (up to 2s, 20x100ms) for the sysfs path to exist, then reading back the applied value and logging a real confirmed/WARNING result instead of silent best-effort. (2) The kernel's RT throttle (sched_rt_runtime_us, default 950000/1000000 = SCHED_FIFO capped at 95% of any 1-second window) was WITNESSED live via dmesg 'sched: RT throttling activated' correlating with real xrun bursts, because faustHome.compute() alone already measures ~1.02ms of the 1.333ms block budget (~77%) -- close enough to the 95% cap that ordinary scheduling jitter crosses it and the kernel forcibly pauses the audio thread for the rest of that window, strictly worse than letting it run. The throttle exists to protect OTHER tasks sharing a core from RT starvation, but cores 1/3 are isolcpus-removed and carry ONLY aloop's own pinned SCHED_FIFO audio threads -- there is no other task to protect. Fixed by writing -1 (unlimited) to /proc/sys/kernel/sched_rt_runtime_us.

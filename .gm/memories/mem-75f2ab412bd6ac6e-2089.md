Two real bugs in multitranspose.dsp found from user reports of "key based transpose is glitching" and "latent sounding transients when we go du du du", both fixed 2026-09-06. ONE: the absolute pitch-lock did not lock. AGENTS.md described shiftAmount as sampled once per voice at attackEdge and held for the whole sustain, but shiftStep glided toward shiftTarget every sample for the entire note while heldDetNote kept following the detected input pitch. The locked output therefore tracked the input: a +-30 cent input wobble (normal vibrato or decay drift) swings the shift target 58 cents, which is audible as glitching. Fix: heldDetNote and shiftStep both freeze once inLockWarmup closes. TWO: trackingAllowed was (trustedTracker > 0.5) | inLockWarmup, so during the warmup window the detected pitch was taken whether or not the tracker was trusted. pitchtracker.lv2 deliberately holds output at 0.0 for the first ~35ms of a fresh onset, which makes extFreqDetApplies false and routes freqDet to the internal zero-crossing fallback -- the one documented as taking >400ms to converge and drifting non-monotonically. So every fresh note was seeded from the worst available estimate, which is why fast repeated notes sounded wrong on their transients. Fix: trackingAllowed = trustedTracker > 0.5. The transferable lesson: the prose in AGENTS.md was CORRECT and the code had drifted away from it. The project rule says never trust an in-repo comment as ground truth and read what the code does -- that rule still applies, but the productive move here was reading the code AGAINST its own written spec and treating the mismatch as the bug rather than assuming the doc was stale. Also worth knowing for future work on this engine: byte-level MIDI injection to tcp/9401 CANNOT reproduce pitch-tracking bugs, because the tracker analyses the live mic signal and injected key events supply no audio. Diagnostics land in /var/log/aloop.log as [diag-pitchguard] lines showing raw, anchor, cand and streak; an empty pitchguard log during an injected note burst means no input, not a healthy engine.

test/hardware/verify-glitch-no-shift.js confirms (both by static read of apc_grid.cpp/midi.cpp's note 82-86 dispatch and by live telemetry) that glitch/microrepeat engagement is gated purely by fx/microrepeat_div > 0, independent of monitorMode/SHIFT -- pressing a microrepeat latch note (82-86, divisions {1,2,4,8,16} per apc_grid.cpp's onMicrorepeatOn table, note 82 = division 1) engages glitch_engaged=true in telemetry while monitor_mode stays false, i.e. glitch works without holding SHIFT. This verifies STATE reaching the DSP correctly via the glitch_engaged/monitor_mode telemetry fields (src/control/telemetry.cpp) -- it does NOT verify audible/recorded content, which needs real audio analysis or a human's ears; if this state-level check passes but a user still reports the bug, the remaining gap is specifically in dsp/aloop.dsp's audio content routing, not control-surface dispatch. Not currently documented in AGENTS.md's SHIFT/monitorfold section.

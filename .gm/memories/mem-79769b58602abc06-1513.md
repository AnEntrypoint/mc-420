config/aloop.conf (shipped device tunables, /etc/aloop.conf on flash) -- facts not already in AGENTS.md, drained from its comments: (1) instrument_device_match (default 'AIR 192') resolves the real instrument_device by substring-matching against /proc/asound/cards at EVERY ALSA-open attempt, because USB enumeration order (which card lands on hw:0) is not stable across boots -- WITNESSED live: the APC Key25's own USB audio interface won the enumeration race and took card 0, silently starving the real instrument audio path. Leave instrument_device_match blank to force the raw instrument_device index instead. (2) [wifi]'s ap_ssid key is DECORATIVE/dead -- nothing in src/ actually reads it; the real mesh SSID is set in src/net/config/hostapd.conf (host side) and wpa_supplicant.conf (join side), which autoap.sh actually uses. The config key is kept only so the value is discoverable next to other wifi settings; all three must be changed together if the SSID ever changes. (3) [remote]'s token line: commenting it out (leaving it unset) DISABLES the whole udp/4446 listener -- no remote reboot AND no remote log-tail (image/aloop-logtail.js's LOGTAIL verb shares this same listener, see the separate aloop-logtail.js memory note). Setting a token enables both. Treat the token like a password, not a feature flag -- anyone who knows it can reboot the device over the network. disable_core3_lv2 and the [storage] ring-recording description are already fully covered in AGENTS.md verbatim, no new fact there.
